Can AI know when it's wrong? · Post 4, how the shrinking worked

Shrinking the credit models

Quantization stores a model's weights in fewer bits so it needs less memory. Post 4 did this to three AI models fine-tuned on 20,000 credit-card customers: Kev-0.8B, Kev-4B and Qwen3.5-4B, at 8, 4, 3 and 2 bits. Every version then estimated the chance of default for the same 2,000 test customers. Start with what happens to one small group of weights.

What got shrunk

Only the linear layers were rounded: the large weight matrices inside every layer of the model, which hold almost all of its weights. The parts that read the text in and the answer out stayed at 16 bits, so the shrunk model takes the same input and gives the same kind of answer.

How every run was checked

The same seven steps ran for each model at each precision.

  1. 01

    Merge the fine-tune into the model

    Each model was fine-tuned with a LoRA, a small set of weight changes kept beside the model. Those changes were added to the base weights in 32-bit and rounded once to 16-bit. That leaves one model to shrink, the way it would ship.

  2. 02

    Swap in the shrunk layers

    Each 16-bit linear layer was replaced by a bitsandbytes or HQQ layer at the chosen precision. No customer data is used to do this. The code refuses any library version except the pinned ones, bitsandbytes 0.50.2 and HQQ 0.2.8.post1.

  3. 03

    Serve every precision the same way

    Full size was run again on the same serving path as the shrunk versions, rather than borrowing post 3's faster setup, so the timings compare like with like.

  4. 04

    Check the path before shrinking anything

    Full size, served through the new code, had to repeat post 3's answers for 50 tune customers, no more than 0.02 apart on average. A broken merge or a lost readout would move answers by tenths.

    Model

  5. 05

    Score 4,000 customers at each precision

    A 20-customer smoke test first, then 2,000 tune and 2,000 test customers, one at a time. All 18 runs (three models, six precisions) finished, and none failed.

  6. 06

    Fit the correction on tune

    Each run also got the series' usual correction: Platt or isotonic, chosen by 5-fold cross-validation on the tune customers. Platt won for all 18.

  7. 07

    Compare with the model's own full-size run

    On the same 2,000 test customers: how far the answers moved, ranking (AUC), calibration, lending profit, memory and time.

What it did to the answers

Pick a model and a precision. Each version is compared with its own full-size run on the same 2,000 test customers, 22.1% of whom defaulted.

Precision

8-bit and 4-bit barely moved anything. At 3 bits the order of customers starts to shuffle. At 2 bits all three models break: AUC falls to between 0.43 and 0.60, near a coin flip, and the average prediction jumps to 36–67%.
